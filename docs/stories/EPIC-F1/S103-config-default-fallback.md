# S103 用户故事：默认兜底与配置切换事件

**用户故事**：作为用户，我希望无匹配配置时回退默认配置并在切换时通知面板，以便任何应用下工具都可用。

## 验收标准（Given-When-Then）

- **AC4-1**：Given 焦点进程无匹配配置（S102 返回 None），When 请求当前配置，Then 回退加载 `default.toml` 的按钮列表。
- **AC4-2**：Given 焦点进程匹配到某配置，When 配置被激活，Then 通过事件总线派发 `ConfigSwitched` 事件（含目标配置名）。
- **AC4-3**：Given 面板订阅 `ConfigSwitched` 事件，When 事件派发，Then 面板收到通知并可刷新按钮列表。
- **AC4-4**：Given 配置加载失败，When 尝试加载，Then 返回明确错误且不影响应用其他模块运行（隔离异常）。

## 任务清单

1. 实现 `get_current_config()`：优先按进程匹配，无匹配回退默认
2. 实现事件总线（最小实现：`tauri::Emitter` 或内部事件通道）
3. 实现 `ConfigSwitched` 事件类型与派发逻辑
4. 建立事件订阅接口供 M5 监听
5. 编写单元测试覆盖兜底与事件派发

## 关联需求

- V3 按应用自动切换配置
- N6 按当前焦点进程/窗口自动切换配置文件
- AC5 配置加载失败隔离

## 技术路由
