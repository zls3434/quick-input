# 设计：按钮分组与悬浮窗 Tab 标签

## 背景

悬浮窗按钮数量随画像增长（如 WindowsTerminal.exe 画像已有 26 个按钮），
一屏纵向滚动查找效率低。产品概念 6.1「分组/标签：按钮分组、多页切换」
（P3）已列入完整愿景，本轮实现。

核心诉求（经澄清确认）：

1. **悬浮窗分组依据应用映射的自定义分组**：每个应用画像（AppProfile）
   独立定义自己的分组，悬浮窗 Tab 按当前生效画像的分组渲染。
2. **按钮级 group 字段仅用于设置界面管理**：设置界面按分组归类展示
   按钮方便管理；不参与悬浮窗 Tab 逻辑。
3. **未分组按钮归「默认」分组**：仅当存在其他分组时显示「默认」标签；
   画像未定义任何分组时悬浮窗不显示 Tab 栏，直接显示全部按钮（现状不变）。

## 决策

采用「分组对象嵌套按钮」结构 + 前端 Tab 渲染：

- `AppProfile` 新增 `groups: Vec<ButtonGroup>`，`ButtonGroup { name, buttons }`
  按组嵌套按钮；保留原 `buttons` 平铺字段兼容旧配置。
- `ButtonConfig` 新增 `group: Option<String>` 管理维度字段（设置界面用）。
- 悬浮窗 Tab 仅在「当前生效的是画像且该画像定义了 groups」时显示，
  位置在右上角控制按钮区左侧。
- 内存模型归一化：读配置时画像 groups 展平为「按钮 + group 值」，
  写配置时按 group 值反向聚合为 groups 嵌套，避免两套数据模型。

## 关键机制

### 1. 配置模型（backend `src/config/model.rs`）

```rust
/// 按钮分组（画像级）：组名 + 组内按钮
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub struct ButtonGroup {
    pub name: String,
    #[serde(default)]
    pub buttons: Vec<ButtonConfig>,
}

// ButtonConfig 新增（管理维度，可选）：
#[serde(default, skip_serializing_if = "Option::is_none")]
pub group: Option<String>,

// AppProfile 新增（悬浮窗分组依据，可选）：
#[serde(default, skip_serializing_if = "Vec::is_empty")]
pub groups: Vec<ButtonGroup>,
```

- `group` 空字符串在解析/展平时归一为 `None`。
- 兼容：旧配置仅有 `profiles.buttons` → 无 groups，悬浮窗无 Tab。

### 2. 归一化（展平 / 聚合）

- **读（配置 → 内存）**：`AppProfile::flatten()` 将 `groups[].buttons` 展平
  到统一按钮视图，按钮携带其分组名（`group: Some(group_name)`），
  无 group 的 `buttons` 平铺按钮保持 `group: None`。
- **写（内存 → 配置）**：`AppProfile::regroup()` 将按钮按 `group` 值
  聚合为 `groups`（按首次出现顺序），无 group 按钮留在 `buttons`。
- 序列化 round-trip 测试须覆盖：展平再聚合后结构与原结构等价。

### 3. 校验扩展（`ConfigFile::validate`）

- 画像内分组名非空、大小写不敏感唯一。
- 画像内全部按钮 id 唯一（含各 `groups[].buttons` 与 `buttons`，跨组不重复）。
- 不校验按钮 `group` 值与画像分组名的对应关系（按钮 group 是独立管理维度）。

### 4. 悬浮窗 Tab 栏（`src-tauri-app/src/routes/+page.svelte`）

- 数据流：`get_buttons` 返回当前生效画像的**分组视图**：
  `{ groups: [{ name, buttons }], default_buttons: [...] }`；
  未匹配画像 / 画像无 groups 时返回 `groups: []`（前端不渲染 Tab）。
- Tab 栏渲染条件：`groups.length > 0` 或（存在分组时）默认组非空。
  - 画像定义了 groups → 渲染 Tab 栏；「默认」标签仅当画像
    `buttons`（无 group 平铺按钮）非空时显示，固定排在首位。
  - 画像无 groups → 不渲染 Tab 栏，直接显示全部按钮（现状）。
- 位置：顶部右上角控制按钮区（`.ctrl-bar`）左侧同一水平行，绝对定位。
- 交互：点击 Tab 切换当前显示分组；默认选中首个标签；切换 Tab 仅影响
  展示，不影响注入、模板输入、长按回车等既有交互。
- 竖向布局：Tab 栏占一行，按钮列表区域下移；横向布局：Tab 栏占顶行，
  高度自适应逻辑计入 Tab 行。

### 5. 设置界面（`src-tauri-app/src/routes/settings/+page.svelte`）

- 按钮编辑表单新增「分组」输入框（文本，可留空，占位如"如：git / 运维"）。
- 全局/默认按钮：group 值写入 `ButtonConfig.group`，仅作管理归类展示。
- 画像按钮：保存时 group 值经 `regroup()` 聚合进该画像 groups。
- 按钮列表按分组分组展示（管理视图），方便批量管理。

### 6. 错误处理

- 配置含非法分组（重名 / 跨组 id 重复）→ `validate()` 返回首个
  `ValidationError`，沿用既有「配置错误则回退并提示」流程。
- 前端收到 `groups: []` 空分组视图 → 回退单列表渲染（现状）。

## 测试

### 后端（`src/backend`，TDD）

- `ButtonConfig` group 字段序列化/反序列化；空字符串归一为 None。
- `ButtonGroup` 解析：TOML `[[profiles.groups]]` 嵌套结构解析。
- `flatten()` / `regroup()` round-trip：展平再聚合与原配置等价。
- 校验：分组名重复拒绝、跨组按钮 id 重复拒绝、组名空拒绝。
- 兼容：旧配置（无 groups / 无 group）解析与校验通过。

### 前端（`src-tauri-app`）

- Tab 聚合：分组视图渲染、默认标签显隐、Tab 切换内容、无分组回退。
- 端到端：CDP 实测——画像定义分组后悬浮窗出现 Tab，点击切换按钮组，
  注入功能不受影响。

## 范围（不做）

- 不做独立分组管理页（重命名/排序/删除分组）——通过按钮 group 值编辑完成。
- 不做分组选择记忆（每次默认选中首个标签）。
- 全局按钮 / `default_buttons` 不产生悬浮窗分组（按钮 group 仅管理用）。
- 不涉及跨平台、云同步。
