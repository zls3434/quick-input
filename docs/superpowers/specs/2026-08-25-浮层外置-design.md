# 设计：tooltip 与右键菜单外置独立浮层窗口

## 背景

悬浮窗（横向约 736x79 / 纵向约 316x409）中，按钮的鼠标悬停说明
（Tooltip）与右键自定义菜单因超出悬浮窗物理边界而被裁剪：

- `html/body` 与 `.quickinput-overlay` 均 `overflow: hidden`，WebView2
  内容在窗口物理边界处裁剪，任何窗口内绝对定位的浮层无法超出窗口显示。
- Tooltip 固定定位在按钮上方（`bottom: calc(100% + 6px)`），横向布局下
  按钮位于窗口顶部，窗口吸附屏幕顶部时 tooltip 整体被裁。
- 右键菜单 `position: fixed` 且仅用 `Math.min` 钳制在窗口右下角内：
  横向窗口高度约 79px 而菜单自身约 60~90px 高，必然溢出被裁，且无方向翻转。

用户明确要求：**不接受内部滚动或调整窗口大小**，将 tooltip 与右键菜单
作为独立层级渲染到悬浮窗**外面**，保证内容完整可见。

## 决策

新增独立浮层窗口 `floater`（透明、无边框、置顶、跳过任务栏、隐藏启动），
动态承载 tooltip 与右键菜单两种内容。悬浮窗通过 IPC 控制浮层的显示、
隐藏、内容与定位，浮层窗口始终显示在悬浮窗之外、屏幕工作区之内，
彻底摆脱悬浮窗尺寸约束。

### 架构

```
overlay 窗口（业务载体）              floater 窗口（纯显示层）
  ├─ Tooltip hover ──invoke──> Rust ──emit──> 渲染 tooltip
  ├─ 右键按钮 ──────invoke──> Rust ──emit──> 渲染菜单
  │                                │
  └─<──emit 菜单动作──── Rust <──invoke 菜单项点击
```

- 悬浮窗仍是唯一业务逻辑载体：菜单项动作（模板输入）由浮层转发回
  悬浮窗执行。
- 浮层窗口不承载任何业务状态，仅按事件渲染内容。

## 关键机制

### 1. 窗口定义

`tauri.conf.json` 注册 `floater` 窗口（与 settings 同模式）：

- `visible: false`（启动隐藏）、`focus: false`
- `transparent: true`、`decorations: false`、`alwaysOnTop: true`
- `skipTaskbar: true`、`resizable: false`
- 初始尺寸 1x1，运行时由 Rust 按内容尺寸调整
- 入口路径 `/floater`（SPA fallback，复用 index.html + 前端路由）

### 2. IPC 协议

| 方向 | 名称 | 参数 | 说明 |
|---|---|---|---|
| overlay → Rust | `show_floater` | `{ kind, payload, anchor }` | `kind: "tooltip" \| "menu"`；`anchor` 为按钮在悬浮窗内的逻辑像素 `{x,y,w,h}` |
| overlay → Rust | `hide_floater` | - | 隐藏浮层 |
| Rust → floater | `floater://show` | `{ kind, payload, placementHint }` | 渲染内容 |
| Rust → floater | `floater://hide` | - | 清空内容 |
| floater → Rust | `floater_ready` | `{ w, h }` | 内容渲染完成，报告测量尺寸 |
| floater → Rust | `floater_action` | `{ id }` | 菜单项点击 |
| Rust → overlay | `floater-menu-action` | `{ id }` | 转发菜单动作 |

**两阶段定位**（避免闪烁）：`show_floater` 仅记录锚点并触发渲染 →
浮层前端渲染后测量 `document.body` 尺寸并上报 `floater_ready` →
Rust 计算最终位置，`set_size` + `set_position` + `show`。
测量期间窗口保持隐藏，无可见闪烁。

### 3. 定位算法

输入：锚点矩形（overlay 逻辑像素）+ 浮层内容尺寸（物理像素）+ overlay
所在显示器工作区。

1. 锚点物理坐标：`anchor_px = overlay.outer_position + anchor * scale`。
2. 计算上下可用空间：上方 `anchor.top - wa.top`，下方 `wa.bottom - anchor.bottom`。
3. 垂直方向：优先显示在锚点下方（菜单惯例）；下方不足且上方足够时
   翻转到上方；两侧都不足时钳制在工作区内（仅极端长文本场景）。
4. 水平方向：菜单与锚点左对齐、tooltip 相对锚点水平居中；越界时
   clamp 到工作区，保证浮层完整可见。
5. 最终位置整体 clamp 到工作区边界，永不超出屏幕。

### 4. 焦点与鼠标

- **tooltip**：Rust 端给浮层窗口设置 `WS_EX_NOACTIVATE | WS_EX_TRANSPARENT`
  （鼠标穿透，复用现有窗口样式切换先例），前端 CSS `pointer-events: none`
  双保险，完全不干扰用户操作。
- **菜单**：浮层窗口保持可激活（不加 NOACTIVATE），可接收鼠标点击；
  悬浮窗本身是 NOACTIVATE 设计，两者无焦点冲突。菜单显示时浮层成为
  前台窗口（用户右键的预期行为），隐藏时若浮层仍是前台则还原前台给
  右键前的窗口（复用现有 `DIALOG_PREV_FOREGROUND` 模式）。

### 5. 关闭闭环

- **tooltip**：按钮 `mouseleave` → `hide_floater`；hover 快速切换按钮时
  直接刷新内容不闪断（模块级占用者标记）。
- **菜单**：
  - 点击菜单项 → `floater_action` → Rust 隐藏 + 转发动作到悬浮窗。
  - 点击悬浮窗任意处 → overlay 前端 `mousedown` capture → `hide_floater`。
  - 点击其他应用/桌面 → 浮层窗口 `Focused(false)` → Rust 隐藏。
- **overlay 移动/缩放**：Rust 端监听 overlay 的 `Moved`/`Resized` →
  隐藏浮层（拖动/缩放期间浮层不会处于可交互状态）。

## 改动点

### 1. 新增 `src-tauri-app/src-tauri/src/floater.rs`

- 命令：`show_floater`、`hide_floater`、`floater_ready`、`floater_action`。
- 定位函数 `compute_floater_placement(anchor_px, size, work_area, kind)`
  （纯函数，可单测）。
- 窗口样式切换：`set_floater_click_through(app, enabled)`（tooltip 用）。
- 浮层失焦监听：`WindowEvent::Focused(false)` 且当前为菜单 → 隐藏。
- overlay `Moved`/`Resized` 监听 → 隐藏浮层。
- 模块级状态：当前浮层 kind、右键前前台窗口句柄。

### 2. `src-tauri-app/src-tauri/src/lib.rs`

- 注册 `floater` 模块命令与窗口事件处理。

### 3. `src-tauri-app/src-tauri/tauri.conf.json`

- 新增 `floater` 窗口配置（见上文）。

### 4. 新增 `src-tauri-app/src/routes/floater/+page.svelte`

- 监听 `floater://show`/`floater://hide`，按 kind 渲染 tooltip 或菜单。
- 渲染后测量尺寸上报 `floater_ready`。
- 菜单项点击上报 `floater_action`。
- 样式复用现有 tooltip/ctx-menu 视觉（深色卡片、圆角、阴影、小三角）。

### 5. 改造 `src-tauri-app/src/lib/Tooltip.svelte`

- 删除 DOM `.tooltip` 渲染。
- `mouseenter`：取按钮 `getBoundingClientRect()`，`invoke("show_floater", { kind: "tooltip", text, anchor })`。
- `mouseleave`：`invoke("hide_floater")`。
- 模块级占用者标记：hover 切换时直接刷新内容不闪断。

### 6. 改造 `src-tauri-app/src/routes/+page.svelte`

- `showCtxMenu`：删除原生 DOM 菜单构建，改为
  `invoke("show_floater", { kind: "menu", items, anchor })`。
- 移除 `removeCtxMenu` 及 `.ctx-menu/.ctx-item/.ctx-hint` 样式、
  `blockFocusSteal` 相关逻辑。
- 新增 `listen("floater-menu-action")`：执行模板输入动作（复用现有
  openTemplateDialog 流程）。
- overlay `mousedown` capture：菜单打开期间点击悬浮窗 → `hide_floater`。

## 兼容性

- 悬浮窗几何、吸附、自愈机制均不涉及，无行为变化。
- 模板输入弹窗（template-dialog）保持现状，不在本次范围
  （横向布局下同样可能溢出，列为已知限制，后续单独处理）。

## 测试

- Rust 单测：`compute_floater_placement` 全场景（上下翻转、水平越界、
  多尺寸、工作区钳制）。
- 前端：类型检查零错误。
- 手动实测：横向/纵向布局、窗口吸附屏幕顶/底部、多按钮快速 hover、
  菜单点击/外部点击关闭、overlay 拖动时浮层隐藏。
