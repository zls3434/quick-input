## 1. 产品名称

QuickInput

**命名说明**："QuickInput" 意为"快速输入"，直接点明工具核心价值——通过点击置顶浮层按钮，向当前焦点输入框即时输入预设文本或命令，减少重复敲打与切换窗口的成本。

---

## 2. 电梯演讲

> 用一段话清晰说明产品是什么、面向谁、解决什么问题、有何不同。

对于经常需要在各类应用输入框重复输入相同内容（代码片段、API key、常用模板、Shell 命令、邮件短语）的开发者与办公用户，QuickInput 是一个常驻桌面的置顶浮动快捷输入工具。它能够通过点击按钮将预设文本瞬间输入当前焦点输入框，且不打断焦点。与一般的片段管理工具（如 TextExpander、Espanso）不同，QuickInput 提供**透明的置顶按钮面板**与**按当前应用自动切换配置文件**的能力，无需记忆触发词即可即点即输，并保证一键操作不改变输入焦点。

## 3. 核心价值主张

| 编号 | 价值主张 | 对用户的意义 | 量化指标（如有） |
|------|----------|--------------|------------------|
| V1 | **即点即输，不打断输入焦点**：单击按钮即向当前焦点输入框注入预设内容，且点击不改变焦点 | 用户无需切屏、无需复制粘贴、无需重新聚焦，连续在多个输入框间快速填充，大幅提升重复输入效率 | 单次输入从"复制→切换→粘贴→切回"约 5-8 秒，降至点击一次约 1 秒内完成 |
| V2 | **置顶透明浮层，随时可达**：按钮面板常驻屏幕顶层，随叫随用，工具可开机自启 | 工具始终在视野内，无需记忆快捷键或触发词，降低认知负担 | 常用文本输入耗时降低 80% 以上 |
| V3 | **按应用自动切换配置**：识别当前焦点所属进程/窗口，自动加载对应配置文件 | 不同应用（IDE、终端、浏览器、邮件）各自维护专属快捷按钮集，互不干扰，且**批量自定义**通过 TOML 配置实现 | 用户在多个应用间切换时 0 配置切换，配置维护成本趋近于 0 |
| V4 | **悬浮注释说明**：鼠标悬停按钮弹出注释，说明该按钮的用途与内容 | 降低记忆负担，尤其适合团队共享的常用命令/模板集，新人可快速上手 | 减少误用与记忆错误，提升团队协作效率 |

## 4. 目标用户画像

### 用户画像 A：前端/后端开发者

- **画像名称**：全栈开发者"小王"
- **demographics**：年龄段 22-35 / 地域 不限 / 行业 互联网/软件
- **职责**：日常使用 IDE（VS Code、IntelliJ）、终端（PowerShell、iTerm2）、浏览器 DevTools 等工具进行编码、调试、Git 操作
- **典型场景**：频繁输入 Git 命令（`git commit -m`、`git push`）、SQL 查询片段、API 请求模板、日志调试命令、代码模板 / 占位符
- **核心诉求**：减少重复输入，不打断编码流，不同 IDE 和终端之间自动切换对应的快捷按钮
- **当前痛点**：使用片段管理工具（如 Espanso）需要记忆触发词，或切换到片段仓库复制粘贴，打断思维流

### 用户画像 B：运维/DevOps 工程师

- **画像名称**：运维工程师"老张"
- **demographics**：年龄段 25-40 / 地域 不限 / 行业 互联网/云计算/企业 IT
- **职责**：日常维护多台服务器、监控平台、CI/CD 流水线、Kubernetes 集群，需要频繁在终端、Web 控制台、看板间切换
- **典型场景**：输入巡检命令（`kubectl get pods`、`docker ps`、`tail -f`）、运维脚本、SSH 连接命令、监控查询语句、故障排查模板
- **核心诉求**：跨终端/Web 控制台快速输入重复命令，运维现场快速响应，减少疲劳性输入错误
- **当前痛点**：频繁在多个 SSH 会话和 Web 管理面板间切换，手动输入长命令容易出错，且没有统一的快捷输入面板

### 用户画像 C（次要）：办公/客服人员

- **画像名称**：客服主管"李姐"
- **demographics**：年龄段 25-45 / 地域 不限 / 行业 电商/金融/企业服务
- **职责**：日常处理工单、回复邮件、填写 CRM 系统、录入标准化数据
- **典型场景**：输入常用回复模板、标准话术、FAQ 答案、客户信息模板
- **核心诉求**：在工单系统、邮件客户端、CRM 之间快速输入标准回答，减少重复打字的劳累
- **当前痛点**：需要在多个系统间复制粘贴，文本模板管理混乱，切换系统后需重新定位模板

## 5. 用户需求分析（Kano 模型）

| 需求编号 | 需求描述 | Kano 分类 | 优先级 |
|----------|----------|-----------|--------|
| N1 | 置顶浮动层常驻显示 | 基本型（Must-be） | P0 |

| N3 | 点击按钮后不改变当前焦点 | 基本型（Must-be） | P0 |
| N4 | 按钮对应内容可自定义设置 | 期望型（One-dimensional） | P0 |
| N5 | 悬浮显示注释说明 | 期望型（One-dimensional） | P1 |
| N6 | 按当前焦点进程/窗口自动切换配置文件 | 期望型（One-dimensional） | P1 |
| N7 | 配置文件持久化与批量自定义（TOML） | 期望型（One-dimensional） | P1 |
| N8 | 开机自启 | 兴奋型（Attractive） | P2 |
| N9 | 跨平台支持 | 兴奋型（Attractive） | P2 |

**Kano 分类说明**：
- 基本型：缺失会导致极度不满，存在也不会带来满意。
- 期望型：满足程度越高，满意度越高。
- 兴奋型：缺失无影响，存在会带来惊喜。
- 无差异型：无论是否存在，用户都不在意。
- 反向型：存在反而引起不满。

## 7. 技术风险

| 风险编号 | 风险描述 | 概率 | 影响 | 应对策略 |
|----------|----------|------|------|----------|
| TR1 | **单击注入不改变焦点**：GUI 点击按钮时，点击本身可能让浮层获得焦点，导致注入失败或注入到浮层自身 | 高 | 高 | 浮层设置为"不激活"（点击不激活窗口，如 Windows WS_EX_NOACTIVATE、macOS NSWindow 不 makeKey）；注入前临时记录原焦点句柄，输入后恢复；用 `SendInput`/`CGEvent` 直接向目标注入而非依赖焦点 |
| TR2 | **跨平台输入注入实现差异**：Windows / macOS / Linux 的文本注入机制不同（Windows `SendInput`、macOS 需 Accessibility 权限 + CGEvent、Linux 走 `xdotool`/`wtype`） | 中 | 高 | 抽象统一的注入层接口，各平台独立实现；macOS 增加权限引导与检测；Linux 依赖外部工具需打包附带或提示安装 |
| TR3 | **焦点进程/窗口识别不一致**：不同平台、不同应用（尤其终端、WebView、权限受限进程）获取"当前焦点窗口所属进程"的可靠性不同 | 中 | 中 | 分平台实现窗口/进程枚举（Windows 用 Win32 枚举、macOS 用 CGWindowList/NSWorkspace、Linux 用 X11/Wayland 协议）；提供"未匹配则回退默认配置"的兜底策略 |
| TR4 | **置顶浮层在特殊环境失效**：Wayland 合成器、远程桌面、全屏游戏等场景下置顶/置顶及输入模拟可能受限 | 中 | 中 | 明确不支持范围；Wayland 下提供 XWayland 回退或文档说明；远程桌面场景降级为普通浮层 |
| TR5 | **开机自启与权限**：作为常驻 GUI 工具，开机自启实现随平台而异，且首次运行需引导用户授权辅助功能/输入监听权限 | 中 | 中 | 分平台实现自启（Windows 注册表/启动文件夹、macOS LaunchAgent、Linux 用户自启动）；首次运行引导授权并给出手动排查说明 |

## 8. 市场定位

- **目标市场**：个人桌面效率工具市场——面向开发者、运维工程师与高频重复输入用户，提供轻量、即点即输的快捷输入解决方案
- **主要竞品**：
  - **TextExpander**（macOS/Windows）：成熟的文本片段扩展工具。优势是引导词触发、团队共享、生态完善；劣势是**依赖记忆触发词**，无"置顶浮层即点即输"的交互，且收费
  - **Espanso**（跨平台，开源）：轻量文本扩展工具。优势是开源免费、跨平台、配置驱动；劣势是无置顶按钮面板，触发依赖触发词/快捷键，学习成本较高
  - **AutoHotkey**（Windows）：通用自动化脚本。优势是灵活强大；劣势是**需要编程编写脚本**，非技术用户门槛高，无可视化浮层
- **差异化定位**：QuickInput 以**"置顶透明浮层 + 单击即输 + 不抢焦点 + 按应用自动切换配置"**为核心差异化，既不需要记忆触发词（区别于 TextExpander/Espanso），也不需编写脚本（区别于 AutoHotkey），提供"所见即所得"的零门槛快捷输入体验
- **商业模式**：开源核心 + 免费增值（个人免费、团队协作/云同步高级功能收费），或 Open Core 模式
- **市场进入策略**：以开源 + 开发者社区切入，发布 Windows/macOS/Linux 跨平台版本，通过 GitHub 与产品社区积累早期用户与反馈，优先服务开发者与运维人群
